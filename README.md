# DocuFlow — система хранения и согласования документов

DocuFlow — прототип системы управления документами с поддержкой версионирования, согласования, разграничения прав доступа и поиском (включая «умный» поиск по вопросам). Проект включает:

- **Бэкенд** на FastAPI + SQLAlchemy + PostgreSQL;
- **Фронтенд** (HTML/CSS/JS) c простым SPA-интерфейсом;
- Docker Compose для быстрого запуска с PostgreSQL.

## Почему FastAPI

FastAPI обеспечивает высокую скорость разработки, декларативные схемы данных через Pydantic и удобную интеграцию с асинхронными и синхронными зависимостями. Для прототипа с богатыми REST-эндпоинтами FastAPI позволяет быстро описать бизнес-логику, а затем масштабировать и подключать дополнительные сервисы (например, внешний сервис поиска по эмбеддингам).

## Быстрый старт

### 1. Подготовка окружения

```bash
cp .env.example .env
```

При необходимости измените параметры подключения к базе данных и секретный ключ.

### 2. Запуск через Docker Compose

```bash
docker compose up --build
```

Сервисы:
- `backend`: FastAPI-приложение на порту `8000`;
- `db`: PostgreSQL 15 на порту `5432` (проброшен наружу для локальных подключений).

После запуска интерфейс будет доступен по адресу <http://localhost:8000>.

### 3. Локальный запуск без Docker

1. Установите PostgreSQL и создайте базу данных `docflow`.
2. Создайте и активируйте виртуальное окружение Python 3.11.
3. Установите зависимости и запустите сервер:

```bash
pip install -r backend/requirements.txt
export $(grep -v '^#' .env | xargs)  # загрузка переменных окружения
uvicorn app.main:app --reload --app-dir backend/app
```

### 4. Создание тестовых данных

После первого запуска приложение автоматически создаёт таблицы. Для быстрой проверки:

1. Войдите в систему через форму логина, предварительно зарегистрировав первого пользователя (кнопка «Регистрация» реализована через эндпоинт `/api/auth/register`, можно вызвать через cURL или Swagger UI по адресу <http://localhost:8000/docs>).
2. Через эндпоинт `/api/admin/roles` создайте роли `admin`, `manager`, `employee`, `viewer`.
3. Назначьте роль `admin` своему пользователю через `/api/admin/users/{id}`.
4. Добавьте отделы (`/api/admin/departments`).
5. Либо выполните подготовительный скрипт (при запущенном бэкенде):

   ```bash
   docker compose exec backend python -m app.scripts.seed_admin admin@example.com SuperSecure "Администратор"
   ```

### 5. Загрузка первого документа

1. В разделе «Новый документ» заполните форму, выберите файл формата `.docx`, `.pptx`, `.xlsx` или `.pdf`.
2. Укажите уровень доступа и согласующих (через запятую). Система создаст запись, версию, заполнит текстовый индекс.
3. Документ появится в списке. Нажмите «Открыть» чтобы просмотреть метаданные, версионность, историю согласований и распечатать страницу (кнопка «Отправить на печать»).

### 6. Проверка поиска

- **Полнотекстовый поиск**: используйте поле поиска на главной странице, результат фильтруется по правам доступа и показывает совпадения по названию/тексту/метаданным.
- **«Умный» поиск**: во вкладке «Умный поиск» задайте вопрос свободным текстом. Система выполнит ключевое слово-поиск, соберёт выдержки и предложит краткий ответ. Архитектура сервиса (`backend/app/services/search.py`) позволяет заменить логику на векторный поиск/LLM без изменений API.

## Архитектура проекта

```
backend/
  app/
    api/              # REST-эндпоинты (auth, documents, admin)
    core/             # конфигурация, подключение к БД, безопасность
    models/           # SQLAlchemy ORM-модели
    schemas/          # Pydantic-схемы ответов/запросов
    services/         # бизнес-логика (поиск, ACL)
    utils/            # обработка файлов
frontend/
  index.html          # SPA-интерфейс
  static/css          # стили
  static/js           # взаимодействие с API
storage/              # сохраняемые файлы документов
```

### Модели данных

- `User`, `Role`, `Department` — пользователи, их роли и отделы.
- `Document` — основная сущность документа с метаданными и параметрами доступа.
- `DocumentVersion` — история версий с привязкой к пользователю и снимком метаданных.
- `DocumentApproval` — записывает статус согласования каждым пользователем и комментарии.
- `DocumentAccessRule` — детализированные правила доступа (по пользователям/отделам).
- `DocumentTextIndex` — хранит извлечённый текст и краткое резюме для поиска.
- `AuditLog` — журнал действий (создание, обновление, согласование, изменение прав).

### Основные эндпоинты

| Группа | Маршрут | Описание |
|--------|---------|---------|
| Auth | `POST /api/auth/register` | Регистрация пользователя |
| Auth | `POST /api/auth/login` | Получение JWT токена |
| Documents | `GET /api/documents/` | Список документов с учётом ACL |
| Documents | `POST /api/documents/upload` | Загрузка нового документа |
| Documents | `PUT /api/documents/{id}` | Обновление метаданных/статуса |
| Documents | `POST /api/documents/{id}/upload-version` | Загрузка новой версии |
| Documents | `POST /api/documents/{id}/review/{approve|reject}` | Согласование |
| Documents | `GET /api/documents/search` | Полнотекстовый поиск |
| Documents | `GET /api/documents/smart-search` | «Умный» поиск |
| Admin | `GET/POST /api/admin/users` | Управление пользователями |
| Admin | `GET/POST /api/admin/roles` | Управление ролями |
| Admin | `GET/POST /api/admin/departments` | Управление отделами |
| Admin | `GET /api/admin/audit-logs` | Последние записи журнала |

## Расширение и доработка

- **Подключение LLM/эмбеддингов**: реализовать адаптер в `services/search.py`, заменив простую частотную метрику на запрос к внешнему сервису и сохранение векторных индексов.
- **Расширенные права**: использовать таблицу `DocumentAccessRule` для записи прав редактирования и интеграции с UI.
- **Интеграция с внешними системами**: дополнить `AuditLog` отправкой событий во внешние шины/почту.
- **Тесты**: добавить pytest-наборы для проверок бизнес-логики и ACL.
